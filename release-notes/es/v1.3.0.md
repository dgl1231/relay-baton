# v1.3.0 — Vista previa de rutas & pulido

Versión de pulido tras GA: la sugerencia de enrutamiento se convierte en un comando de solo lectura de primera clase, la salida amigable del CLI se extiende más allá de `run`, las funciones de v1.2.0 quedan totalmente documentadas y se incluye un escenario de demo listo para grabar. Restricciones fuertes intactas: local-first, determinista, solo subprocess, confirmation-first, sin demonio.

## Añadido

- **`relay-baton route "<task>" [--json]`** — vista previa de solo lectura de la sugerencia de enrutamiento. Resuelve la cadena exactamente como `run` (banderas > asignación del work-item > proyecto > config) y muestra cómo las etiquetas `strengths` del registro reordenarían la cadena para la tarea, con las palabras clave coincidentes por agente. Nunca lanza un agente ni escribe estado de sesión.
- **Escenario de demo** — `scripts/demo/demo.sh` + `scripts/demo/fake-agent.mjs`: recorrido determinista fallback → handoff compacto → reanudación con agentes falsos (sin ejecutar codex/claude reales, sin gastar cuota). Grábalo con `asciinema rec -c "bash scripts/demo/demo.sh" demo.cast`.

## Mejorado

- **Salida amigable donde importa** — el estilo `ui` de v1.2.0 (✓ / ✗ / ▲ con pistas de «qué probar a continuación») ahora también cubre `doctor`, `init`, `status`, `login` y `handoff`. `doctor`/`login` antes tenían ANSI codificado e ignoraban `NO_COLOR`/no-TTY; ahora degradan correctamente a texto plano.
- **`doctor` muestra el estado de los disparadores** — una línea Core info indica si el bloque opcional `handoffTriggers` está configurado, haciendo descubrible la función de v1.2.0.
- **Documentación completa** — `--handoff-now`, el bloque `handoffTriggers` (con JSON de ejemplo), las sugerencias de enrutamiento y `route` están documentados en `docs/COMMANDS.md` (EN+KO), la guía (EN+KO) y la sección de configuración del README.

## Compatibilidad

- Sin cambios incompatibles; sin cambios de esquema. `route` es puramente aditivo.
