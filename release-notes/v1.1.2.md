# v1.1.2 — Release pipeline hotfix (bundler on PATH)

Patch release. No behavior changes — second fix to the **release workflow** so
the per-OS standalone binaries actually build.

## Fixed

- **`release.yml` — `npx --yes esbuild/postject` failed with exit 127.** Once
  v1.1.1 made the workflow valid YAML, all three matrix jobs ran but failed
  because `npx --yes <tool>` did not reliably expose the tool's bin on the CI
  runners (`command not found`). The workflow now installs the bundler/injector
  explicitly with `npm install -g esbuild postject` and calls them directly —
  the same recipe verified locally end-to-end (esbuild → SEA blob → node copy →
  postject inject → codesign → `--version` smoke test). This touches only the
  global npm store, not the repo lockfile, so the build/test CI stays green.

## Result

Pushing `v1.1.2` builds `relay-baton-linux-x64`, `relay-baton-macos-arm64`, and
`relay-baton-windows-x64.exe` and attaches them to the v1.1.2 GitHub Release. The
README "latest release" download links resolve to it automatically.
