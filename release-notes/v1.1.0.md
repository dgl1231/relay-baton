# v1.1.0 — Distributable

relay-baton is now something you **download and run**, not only something you
build from source. The CLI remains the engine; the new surfaces are thin shells
over it, and every hard constraint is unchanged (no direct API calls, no key
storage, no auto commit/push/PR, deterministic compaction only).

## Highlights

- **Standalone executables.** Single-file binaries for `linux-x64`,
  `macos-arm64`, and `windows-x64`, built with Node's Single Executable
  Application (SEA) support — no Node install required to run them.
- **Automated release pipeline.** Pushing a `v*` tag triggers
  `.github/workflows/release.yml`, which builds the per-OS binaries and attaches
  them to the GitHub Release. Uses only the default `GITHUB_TOKEN` — no npm
  publish, no extra secrets.
- **Downloads in the README.** Direct "latest release" links so users can grab
  the right binary for their OS.
- **Tauri desktop shell (scaffold).** A new `desktop/` app wraps the CLI as a
  Tauri **sidecar**; the webview calls `relay-baton status/budget --json`. It
  duplicates no logic and lives outside the pnpm workspace, so the TypeScript
  build and test CI are unaffected. The full GUI ships in v1.2.

## How it works

The release job runs `pnpm build`, bundles the compiled CLI (and its workspace
dependencies) into one CommonJS file with `esbuild`, generates a SEA blob from
[`bin/sea-config.json`](../bin/sea-config.json), copies the host `node` binary,
and injects the blob with `postject`. `esbuild` and `postject` are invoked via
`npx`, so the repository lockfile never changes and the build/test workflow
stays green.

## Get it

Grab a binary from the [latest release](https://github.com/dgl1231/relay-baton/releases/latest),
make it executable, and run it:

```bash
# macOS / Linux
chmod +x relay-baton-macos-arm64
./relay-baton-macos-arm64 --version
```

```powershell
# Windows
.\relay-baton-windows-x64.exe --version
```
