# v2.6.0-alpha.0 — Multi-session workspace

v2.6 "Multi-session workspace" — track multiple AI work items in one repo, pin
each to an agent, and run them in parallel without git collisions. Unifies
per-agent session assignment and multi-tasking into one concept: a *named work
item*. All three roadmap items ship in this alpha. (Hard constraints intact:
local-first, deterministic, no daemon, no real-time chat.)

## Added

- **Named sessions (work-item registry).** `WorkspaceManager` owns
  `.ai-session/workspace.json` (the active pointer + work-item list). Named items
  live under `.ai-session/sessions/<name>/`; the legacy flat `.ai-session/` *is*
  the `default` item, so existing repos need **zero migration**. `SessionFiles`
  resolves the active item, so every command (`run`/`handoff`/`status`/`usage`/…)
  transparently operates on it. New CLI:
  `session new | switch | use | items | assign | remove`.
- **Per-agent session assignment.** Each work item can carry an `assignedAgent`
  (`session new --agent <id>` / `session assign <name> <agent>`). `run` uses it as
  the default primary in the relay chain — it beats project/config defaults but
  loses to explicit `--primary`/`--chain`.
- **Safe parallelism via git worktrees.** `session worktree add <name>` backs a
  work item with its own git worktree (default `<parent>/<repo>.worktrees/<name>`,
  branch `relay/<name>`). When the active item has a worktree, `run` executes in
  that isolated checkout — its own working tree and its own `.ai-session` — so
  parallel work items never clobber each other's git state. The registry stays in
  the main repo; still confirmation-first, still no daemon. `session worktree
  remove <name>` detaches it.

## Hard constraints

Unchanged: local subprocess only, deterministic, no daemon, no real-time chat
platform, no direct LLM API client, no API-key passthrough by default, no auto
commit/push/PR.
