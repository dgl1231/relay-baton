# v1.4.0 — Stream de agente amigável e cartões de resultado no desktop

A saída do agente finalmente se lê como uma conversa, não como um despejo de
logs — tanto na CLI quanto no app desktop.

## `--pretty`: stream de agente amigável (CLI)

`run`, `plan`, `execute` e `handoff` aceitam a nova flag opcional `--pretty`.
Ela pede ao CLI do agente seu stream de eventos legível por máquina
(`claude -p --output-format stream-json --verbose`, `codex exec --json`) e o
renderiza como linhas legíveis:

```
● model claude-sonnet-5 · session abc123
  · thinking: need to look at the failing test first
→ Bash: pnpm test --filter core
Fixed the flaky test — two files changed.
✓ agent turn done — in 10,231 tok · out 1,892 tok · $0.0231 · 48.2s
```

- Apenas parsing JSONL determinístico linha a linha — sem chamadas de modelo,
  sem resumos (`parseEvent` dos adapters Codex/Claude).
- Linhas que não parseiam — e agentes sem modo estruturado — voltam ao
  passthrough bruto; o stream bruto completo continua indo para
  `.ai-session/commands.log`.
- A detecção de fallback não muda: os padrões continuam casando nas linhas
  brutas, incluindo o texto de erro dentro dos eventos JSON.
- É opt-in porque versões antigas do CLI do agente podem não suportar as
  flags.

## Desktop: cartões de resultado estruturados no Agent Room

Os resultados dos comandos slash (`/status`, `/budget`, `/git`, `/review`,
`/guard`, `/risk`, `/checkpoints`, `/sessions`, `/resume`, `/workspace`,
`/profile`, `/inventory`, `/inspect`, `/bundle`) agora são renderizados como
cartões estruturados — chips de status, barra de budget, linhas git por
arquivo, checklist de passos do plano — em vez de despejos `JSON.stringify`.
Cada cartão mantém o payload completo atrás de uma seção **raw json**
recolhida. Tudo builders de DOM somente de exibição; a webview segue sem
lógica de negócio.

Corrigido: resultados de `/review` sumiam da timeline logo após renderizar (o
reload da timeline sobrescrevia o cartão).

## Compatibilidade

- `--pretty` é opt-in; a saída padrão não muda.
- `AgentEvent` ganha novos tipos de evento (`system`, `assistant_text`,
  `reasoning`, `tool_use`, `usage`) — aditivo, consumidores existentes não
  são afetados.
- Sem mudanças de config ou de schema de sessão.
