# v2.5.0-alpha.0 — Guarded automation & extensibility

v2.5 "Guarded automation & extensibility" — longer-but-bounded runs and
per-project customization, never an unattended daemon. Both roadmap items ship in
this alpha.

## Added

- **Bounded auto-orchestration (`run --until <n>`).** A new core
  `BoundedOrchestrator` combines `LoopController` (step / budget / divergence
  caps) with the deterministic `GuardrailPolicy` (changed-file / step / budget
  caps) into a single "may I take one more step?" decision. `run --until N` runs
  up to **N extra continue-steps** on the agent that just finished —
  **confirmation-first** (each step prompts unless `--yes`), recording an
  execution checkpoint and a usage event per step. Strictly bounded: it stops on
  the step cap, budget ceiling, divergence, a guardrail violation, or a declined
  prompt. It is **never an unattended daemon** — removing the cap or the
  confirmation gate is out of scope by design.
- **Project recipes / hooks.** Optional `hooks.preHandoff` / `hooks.postExecute`
  arrays of shell commands in config, run at lifecycle points by a new core
  `HookRunner`. **Local-only:** the child env is sanitized exactly like an
  agent's (provider API keys stripped by default), with no daemon and no network.
  Absent config = nothing runs; the chain stops on the first failing command; all
  output is mirrored to `commands.log`. Wired into `run` and `handoff`.

## Hard constraints

Unchanged: local subprocess only, deterministic, confirmation-first for mutating
loops, no unattended autopilot, no direct LLM API client, no API-key passthrough
by default, no network, no auto commit/push/PR.
