# v1.1.1 — Release pipeline hotfix

Patch release. No behavior changes — this fixes the **release workflow** so the
per-OS standalone binaries actually build and attach to the GitHub Release.

## Fixed

- **`.github/workflows/release.yml` line 115 — invalid YAML.** The Windows
  smoke-test step ran `& "dist-bin/..." --version` on a single line. YAML treats
  a leading `&` as an anchor, so the whole workflow failed to parse
  (*"Invalid workflow file … line 115"*) and **no job ran** for the v1.1.0 tag —
  which is why v1.1.0 shipped with only the auto-generated source archives and no
  binaries. The command is now wrapped in a literal block scalar.

## Why a new tag

The release workflow executes the copy of `release.yml` captured **at the tag's
commit**. v1.1.0's tag predates the fix, so a fresh `v1.1.1` tag is the clean,
non-destructive way to re-run the pipeline with the corrected workflow.

## Result

Pushing `v1.1.1` builds `relay-baton-linux-x64`, `relay-baton-macos-arm64`, and
`relay-baton-windows-x64.exe` and attaches them to the v1.1.1 GitHub Release. The
README "latest release" download links resolve to it automatically.
