# relay-baton v0.6.0 Release Notes

Status: **Planning** — work spec. Becomes the release note as items land.

Date (target): 2026-08

## Summary

v0.6 finishes the deferred surface from v0.4/v0.5 and deepens the two v0.5 modes. No new mode. Theme: **make plan-execute and context-compression robust and visible.**

Pick any block independently. Minimum = block A.

## Block A — UI for the new modes (carried from v0.5)

- TUI pane: current `workflowMode`, plan status (`planning`/`plan_ready`/`executing`), `compressing` indicator.
- TUI keys already exist (`q`/`r`/`p`/`d`/`b`/`h`); add `e` = execute no-op preview (no agent launch — TUI never spawns).
- `status` command: show plan-execute fields (planAuthor/executor/planFinalizedAt) + last compression ratio.
- Files: `packages/tui/src/App.tsx`, `packages/cli/src/commands/status.ts`.

## Block B — Plan-execute depth

- **Plan execution receipts** — executor marks `plan.md` Steps `[done]`/`[skipped]`. Verifiable trail. Gate: receipts only append markers, never rewrite step text.
- **Plan diffing** — re-plan shows delta vs previous `plan.md` instead of full rewrite. Keep prior as `plan.<ts>.md` (mirror handoff backup).
- **Multi-turn loop** — executor writes divergence to `errors.md`; `plan --replan` re-engages planner with errors as input. Budget guard: cap loops (e.g. 3) to avoid token runaway.
- Files: `packages/core/src/plan/*`, `packages/cli/src/commands/{plan,execute}.ts`.

## Block C — Context-compression depth

- **Adaptive per-model thresholds** — threshold scaled to active agent's known context size. Config: `contextCompression.perAgentThreshold`.
- **Cross-session compression** — roll past completed sessions' raw artifacts into one archive dir instead of leaving each `.ai-session/`.
- **Semantic summarization** — STILL deferred unless a cost-bounded, deterministic-fallback design lands. MVP rule (no API call in relay-baton process) holds.
- Files: `packages/core/src/token-diet/ContextCompressor.ts`.

## Block D — Adapters + CI matrix (carried from v0.4/v0.5)

- OpenCode / Gemini / Aider adapter scaffolds — only when a real user needs one. Each = `<Name>Adapter.ts` + one mirror test + README row.
- Project-level fallback pattern overrides — `BatonProject.fallbackPatterns?` overlays global.
- macOS / Windows CI matrix — `matrix.os` in `.github/workflows/ci.yml`. Expect ≥1 Windows path/EOL fix.

## Compatibility

- All additive. New config keys optional. New SessionMeta fields optional.
- `plan.<ts>.md` backups mirror existing `handoff.<ts>.md` pattern.
- No breaking change planned.

## Order of Work (suggested)

1. Block A (UI) — small, high-visibility. ~1.5h.
2. Block B receipts + diffing — ~2h. Multi-turn loop last (riskiest).
3. Block C adaptive thresholds — ~1h. Cross-session — ~1.5h.
4. Block D only on demand / when CI cost accepted.
5. Bump 0.6.0, finalize note, tag.

Minimum v0.6 = Block A. Rest layered.

## Out of scope

- Real-time agent chat / DM.
- Self LLM API client.
- Auto commit/push/PR.
- IDE extension, daemon, tmux manager.
