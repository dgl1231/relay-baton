# v1.4.0 — Freundlicher Agent-Stream & Desktop-Ergebniskarten

Agent-Ausgaben lesen sich endlich wie ein Gespräch statt wie ein Log-Dump —
in der CLI und in der Desktop-App.

## `--pretty`: freundlicher Agent-Stream (CLI)

`run`, `plan`, `execute` und `handoff` akzeptieren das neue Opt-in-Flag
`--pretty`. Es fordert vom Agent-CLI dessen maschinenlesbaren Event-Stream an
(`claude -p --output-format stream-json --verbose`, `codex exec --json`) und
rendert ihn als gut lesbare Zeilen:

```
● model claude-sonnet-5 · session abc123
  · thinking: need to look at the failing test first
→ Bash: pnpm test --filter core
Fixed the flaky test — two files changed.
✓ agent turn done — in 10,231 tok · out 1,892 tok · $0.0231 · 48.2s
```

- Ausschließlich deterministisches, zeilenweises JSONL-Parsing — keine
  Modellaufrufe, keine Zusammenfassungen (`parseEvent` der
  Codex/Claude-Adapter).
- Nicht parsbare Zeilen — und Agents ohne strukturierten Modus — fallen auf
  unverändertes Passthrough zurück; der komplette Roh-Stream landet weiterhin
  in `.ai-session/commands.log`.
- Die Fallback-Erkennung bleibt unverändert: Muster matchen weiterhin auf den
  Rohzeilen, einschließlich Fehlertext innerhalb der JSON-Events.
- Opt-in, weil ältere Agent-CLI-Versionen die Flags evtl. nicht unterstützen.

## Desktop: strukturierte Ergebniskarten im Agent Room

Slash-Befehlsergebnisse (`/status`, `/budget`, `/git`, `/review`, `/guard`,
`/risk`, `/checkpoints`, `/sessions`, `/resume`, `/workspace`, `/profile`,
`/inventory`, `/inspect`, `/bundle`) werden jetzt als strukturierte Karten
gerendert — Status-Chips, Budget-Balken, Git-Zeilen pro Datei,
Plan-Schritt-Checklisten — statt als rohe `JSON.stringify`-Dumps. Jede Karte
behält den vollständigen Payload hinter einem eingeklappten
**raw json**-Abschnitt. Alles reine Anzeige-DOM-Builder; die Webview enthält
weiterhin keine Geschäftslogik.

Behoben: `/review`-Ergebnisse verschwanden direkt nach dem Rendern aus der
Timeline (das Timeline-Reload überschrieb die Karte).

## Kompatibilität

- `--pretty` ist Opt-in; die Standardausgabe bleibt unverändert.
- `AgentEvent` erhält neue Event-Typen (`system`, `assistant_text`,
  `reasoning`, `tool_use`, `usage`) — additiv, bestehende Konsumenten sind
  nicht betroffen.
- Keine Config- oder Session-Schema-Änderungen.
