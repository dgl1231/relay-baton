# v1.5.0 — Agents aus der Desktop-App starten

Der Agent Room ist kein reiner Viewer mehr: Er kann jetzt tatsächlich
Agents starten — **confirmation-first**, genau wie es das
AGENT_ROOM-Designdokument immer vorgesehen hat (preview → confirm → run).
Ohne Klick läuft nichts.

## `/run <task>` und „Hier ausführen"

- Neuer Composer-Befehl **`/run <task>`**: baut
  `relay-baton run "<task>" --primary <gewählter Agent> --pretty` — der
  Codex/Claude-Toggle im Header bestimmt jetzt wirklich, wer zuerst läuft.
- **`/plan`, `/execute`, `/handoff`** bauen ebenfalls echte Startbefehle
  (handoff hat `--no-run` verloren).
- Alle öffnen das bestehende Bestätigungsmodal mit dem **exakten Befehl**;
  der neue Button **„Run here"** führt ihn über die gebündelte Sidecar-CLI
  aus (deine lokalen Logins und Quota — relay-baton ruft weiterhin keine
  Provider-APIs auf). Kopieren ins Terminal bleibt möglich.

## Live-Ausführungskarte

Die Agent-Ausgabe streamt in eine Live-Karte der Timeline
(`--pretty`-Format): Tool-Aufrufe, Assistant-Text und der abschließende
Token/Kosten-Beleg erscheinen in Echtzeit. Ein **Cancel**-Button beendet
den Prozess; beim Exit erhält die Karte einen grünen `done`- oder roten
`exit N`-Chip und die Dashboard-Panels aktualisieren sich. Eine Ausführung
gleichzeitig; Ausgabe auf die letzten 400 Zeilen begrenzt; die Karte
überlebt Timeline-Reloads wie jede v1.4.1-Ergebniskarte.

## Intern / Kompatibilität

- Neue Tauri-Capabilities: `shell:allow-spawn` (auf das Sidecar begrenzt)
  und `shell:allow-kill` fürs Abbrechen (nur mit execute wären
  Streaming-Läufe verweigert worden).
- Die GUI bleibt frei von Geschäftslogik: Sie startet die CLI und zeigt
  Zeilen an. Alle Gates (Handoff-Qualität, Token Diet, Redaction,
  Guardrails) laufen in der CLI wie vom Terminal aus.
- Guide-/Tooltip-Texte in allen 4 GUI-Sprachen aktualisiert — die App ist
  jetzt ein „confirmation-first dashboard", kein Read-only mehr.
- CLI-Verhalten unverändert; Versionen im Lockstep.
