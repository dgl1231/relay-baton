# v1.5.1 — Ehrliche Lauf-Endungen und ruhigere Live-Ausgabe

Zwei kleine Nachträge zu „Agents aus der Desktop-App starten" aus v1.5.0,
beide beim Verifizieren eines echten `/run` auf dem Gerät gefunden.

## Fehlgeschlagene Endungen sind jetzt unterscheidbar

Wenn eine Relay-Chain auf einem Agent endete, der **lief, aber mit einem
Wert ungleich null beendete**, beendete `run` (und `execute`) trotzdem mit
`0`. In der Desktop-App zeigte das einen grünen `done`-Chip auf der
Lauf-Karte, obwohl die gestreamte Ausgabe mit
`✗ <agent> exited with code N` endete. Solche Endungen beenden jetzt mit
**`4`**, sodass die Karte ihren Chip rot färbt und Skripte ein
fehlgeschlagenes Ende von einem sauberen unterscheiden können.

Exit-Codes von `run`/`execute`: `0` Erfolg · `1` Agent nicht startbar ·
`2` falsche Nutzung · `3` ein Quality Gate hat den Handoff blockiert · `4`
die Kette endete auf einem fehlgeschlagenen Agent.

## Ruhigere Live-Lauf-Karte

Claude gibt mitten im Turn routinemäßige `rate_limit_event`-Telemetriezeilen
aus. Das sind keine erkannten Events, also gingen sie bisher roh in die
Live-Karte. Sie werden jetzt aus der Anzeige unterdrückt (die Rohzeile
erreicht weiterhin die Fallback-Erkennung und das Log auf der Platte — nichts
geht verloren).

## Kompatibilität

- Keine neuen Befehle oder Flags; Exit-Code `4` ist das einzige neue externe
  Verhalten.
- Desktop- und CLI-Versionen im Lockstep angehoben.
