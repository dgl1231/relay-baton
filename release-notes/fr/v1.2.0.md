# v1.2.0 — Relais plus intelligent & UI conviviale

> Note : les noms de tag v1.1.x ont été utilisés par la ligne « Distributable » pré-GA, donc la première version fonctionnelle post-GA sort en v1.2.0.

Première version fonctionnelle post-GA, avec v2.8 « Smarter relay » et des améliorations d'expérience CLI/bureau. Contraintes fortes intactes : local-first, déterministe, subprocess uniquement, confirmation-first, pas de démon.

## Ajouté

- **Déclencheurs de handoff élargis (opt-in).** Nouveau bloc optionnel `handoffTriggers` (`budgetRatio` / `changedFiles` / `usageTokensProxy`) : permet de *suggérer* de passer le relais même sans motif d'erreur de fallback. Au seuil, demande y/N (ou respecte `--yes`) ; sans configuration, la détection reste uniquement par motif d'erreur. Core : `HandoffTriggerPolicy`.
- **Déclencheur manuel de handoff.** `relay-baton run --handoff-now` relaie vers l'agent suivant après chaque saut sans attendre de signal de fallback (le drapeau lui-même est le consentement explicite).
- **Indications de routage (avis seulement).** Les agents du registre portent des étiquettes de mots-clés `strengths` ; `suggestChain` propose un ordre de chaîne et `run` affiche une indication d'une ligne lorsqu'il diffère. Affichage uniquement — `--chain`/`--primary` explicites l'emportent toujours.

## Amélioré

- **Sortie CLI conviviale.** Nouveaux assistants `ui` sans dépendance (✓ / ✗ / ▲ / → avec des indices atténués « quoi essayer ensuite ») ; sortie de `run` avec des en-têtes de saut et des échecs de gate plus clairs. La couleur se désactive automatiquement en cas de pipe ou avec `NO_COLOR`.
- **Restyling chaleureux du bureau.** Le webview Tauri adopte une palette chaleureuse (thème clair crème, thème sombre chaud, accent terracotta), une police sans pour l'interface, des rayons/ombres plus doux et des événements de conversation en cartes. Affichage uniquement — le webview appelle toujours seulement le sidecar CLI.

## Corrigé

- Les invites de confirmation de `run` ne restent plus bloquées indéfiniment quand stdin n'est pas un TTY (CI/entrée en pipe) : elles refusent automatiquement avec une indication pour passer `--yes`.
- CI Windows : la comparaison de chemins du test worktree développe désormais les chemins courts 8.3.

## Compatibilité

- Aucun changement cassant. La nouvelle clé `handoffTriggers` est optionnelle et validée ; les schémas d'artefacts sont inchangés.
