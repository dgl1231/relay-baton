# v1.5.1 — Fins d'exécution honnêtes et sortie live plus discrète

Deux petits suivis de « lancer des agents depuis l'app de bureau » de
v1.5.0, tous deux trouvés en vérifiant un vrai `/run` sur l'appareil.

## Les fins en échec sont désormais distinguables

Quand une relay chain se terminait sur un agent qui **s'est exécuté mais est
sorti avec un code non nul**, `run` (et `execute`) sortait quand même avec
`0`. Dans l'app de bureau, cela affichait un chip vert `done` sur la carte
d'exécution alors même que la sortie se terminait par
`✗ <agent> exited with code N`. Ces fins sortent désormais avec **`4`**, la
carte colore donc son chip en rouge et les scripts peuvent distinguer une
fin en échec d'une fin propre.

Codes de sortie de `run`/`execute` : `0` succès · `1` agent impossible à
lancer · `2` mauvaise utilisation · `3` une quality gate a bloqué le handoff
· `4` la chaîne s'est terminée sur un agent en échec.

## Carte d'exécution en direct plus discrète

Claude émet des lignes de télémétrie `rate_limit_event` routinières en cours
de tour. Ce ne sont pas des événements reconnus, elles passaient donc en
brut dans la carte en direct. Elles sont désormais masquées de l'affichage
(la ligne brute atteint toujours la détection de fallback et le log sur
disque — rien n'est perdu).

## Compatibilité

- Aucune nouvelle commande ni option ; le code de sortie `4` est le seul
  nouveau comportement externe.
- Versions bureau et CLI en lockstep.
