# v1.3.0 — Aperçu de routage & finitions

Version de finition post-GA : l'indication de routage devient une commande en lecture seule à part entière, la sortie CLI conviviale s'étend au-delà de `run`, les fonctionnalités de v1.2.0 sont entièrement documentées et un scénario de démo prêt à enregistrer est fourni. Contraintes fortes intactes : local-first, déterministe, subprocess uniquement, confirmation-first, pas de démon.

## Ajouté

- **`relay-baton route "<task>" [--json]`** — aperçu en lecture seule de l'indication de routage. Résout la chaîne exactement comme `run` (drapeaux > affectation du work-item > projet > config), puis montre comment les étiquettes `strengths` du registre réordonneraient la chaîne pour la tâche, avec les mots-clés correspondants par agent. Ne lance jamais d'agent, n'écrit jamais d'état de session.
- **Scénario de démo** — `scripts/demo/demo.sh` + `scripts/demo/fake-agent.mjs` : parcours déterministe fallback → handoff compact → reprise avec de faux agents (pas de codex/claude réels, aucun quota consommé). Enregistrez avec `asciinema rec -c "bash scripts/demo/demo.sh" demo.cast`.

## Amélioré

- **Sortie conviviale là où ça compte** — le style `ui` de v1.2.0 (✓ / ✗ / ▲ avec des indices « quoi essayer ensuite ») couvre désormais aussi `doctor`, `init`, `status`, `login` et `handoff`. `doctor`/`login` codaient l'ANSI en dur et ignoraient `NO_COLOR`/non-TTY ; ils se dégradent maintenant correctement en texte brut.
- **`doctor` affiche l'état des déclencheurs** — une ligne Core info indique si le bloc optionnel `handoffTriggers` est configuré, rendant la fonctionnalité v1.2.0 découvrable.
- **Documentation complète** — `--handoff-now`, le bloc `handoffTriggers` (avec JSON d'exemple), les indications de routage et `route` sont documentés dans `docs/COMMANDS.md` (EN+KO), le guide (EN+KO) et la section configuration du README.

## Compatibilité

- Aucun changement cassant ; aucun changement de schéma. `route` est purement additif.
