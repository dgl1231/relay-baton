# v1.3.0 — Предпросмотр маршрутов & полировка

Полировочный релиз после GA: рекомендательная подсказка маршрутизации становится полноценной командой только для чтения, дружелюбный вывод CLI выходит за пределы `run`, функции v1.2.0 полностью документированы, и добавлен готовый к записи демо-сценарий. Жёсткие ограничения без изменений: local-first, детерминизм, только subprocess, confirmation-first, без демона.

## Добавлено

- **`relay-baton route "<task>" [--json]`** — предпросмотр подсказки маршрутизации только для чтения. Разрешает цепочку точно так же, как `run` (флаги > назначение work-item > проект > config), затем показывает, как теги `strengths` из реестра переупорядочили бы цепочку для задачи, с совпавшими ключевыми словами по каждому агенту. Никогда не запускает агента и не пишет состояние сессии.
- **Демо-сценарий** — `scripts/demo/demo.sh` + `scripts/demo/fake-agent.mjs`: детерминированный проход fallback → компактный handoff → возобновление с фальшивыми агентами (без реальных codex/claude, без расхода квоты). Запись: `asciinema rec -c "bash scripts/demo/demo.sh" demo.cast`.

## Улучшено

- **Дружелюбный вывод там, где важно** — стиль `ui` из v1.2.0 (✓ / ✗ / ▲ с подсказками «что попробовать дальше») теперь охватывает и `doctor`, `init`, `status`, `login`, `handoff`. Раньше `doctor`/`login` жёстко кодировали ANSI и игнорировали `NO_COLOR`/не-TTY; теперь они корректно откатываются к простому тексту.
- **`doctor` показывает состояние триггеров** — строка Core info сообщает, настроен ли необязательный блок `handoffTriggers`, делая функцию v1.2.0 обнаружимой.
- **Документация полная** — `--handoff-now`, блок `handoffTriggers` (с примером JSON), подсказки маршрутизации и `route` описаны в `docs/COMMANDS.md` (EN+KO), руководстве (EN+KO) и разделе конфигурации README.

## Совместимость

- Без ломающих изменений; без изменений схем. `route` — чисто аддитивная функция.
