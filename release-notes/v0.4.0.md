# relay-baton v0.4.0 Release Notes

Status: **Planning / In progress** — this document is the v0.4 work spec. It will turn into the final release note as items land.

Date (target): 2026-06

## Summary

v0.4.0 is a "trust the harness" pass. v0.2 added the multi-project layer and v0.3 made it safe. v0.4 makes the *fallback path itself* observable and verifiable.

Goal: when the harness silently does the wrong thing during a Codex → Claude handoff, you should be able to tell. Right now you can't, because the critical orchestration code is untested and the harness emits no duration / history signal.

Scope is intentionally narrow:

- Test coverage for the workflow / handoff / quality-gate path.
- CI on push and PR.
- End-to-end CLI smoke test for the project commands.
- Session duration in `session.json` and a `handoff history` command.

Out of scope (explicitly, to keep v0.4 small):

- OpenCode / Gemini / Aider adapters — defer to v0.5.
- TUI fuzzy switcher / command palette.
- Per-model tokenizer, semantic diff, autopilot. These violate the MVP policy in `CLAUDE.md`.

## Planned Changes

### Test coverage for the critical path

Untested modules that participate in every fallback launch:

- `packages/core/src/workflow/BatonWorkflow.ts` (124 LoC, 0 tests) — assembles the handoff payload.
- `packages/core/src/handoff/HandoffGenerator.ts` — writes `handoff.md`.
- `packages/core/src/handoff/HandoffQualityGate.ts` — blocks fallback if handoff is incomplete.
- `packages/core/src/handoff/TokenDietQualityGate.ts` — blocks fallback if budget is exceeded.
- `packages/core/src/agents/ClaudeCodeAdapter.ts` — Codex adapter is tested; the Claude side is not.

Targets:

- BatonWorkflow: end-to-end handoff build against a fixture `.ai-session/` directory; assert that the resulting `handoff.md` contains task, repo map reference, fallback reason, and is under the profile budget.
- HandoffGenerator: section ordering, reference-only output (no full diff inline), backup-on-overwrite behavior.
- HandoffQualityGate: pass / fail cases for each gate failure reason.
- TokenDietQualityGate: pass / warn / fail cases by profile.
- ClaudeCodeAdapter: default args (`--permission-mode acceptEdits -p "<prompt>"`), env filtering when `--allow-api-key-env` is absent.

### CI workflow

Add `.github/workflows/ci.yml`:

- Triggers: push to `main`, pull_request.
- Steps: checkout, setup Node 20 + corepack, `pnpm install --frozen-lockfile`, `pnpm build`, `pnpm test`.
- One matrix: `ubuntu-latest`. macOS / Windows deferred to v0.5 unless cheap.

The CI run replaces the manual "Validation" sections we removed from older release notes.

### CLI smoke test

`packages/cli/src/__tests__/project.smoke.test.ts`:

- Set `RELAY_BATON_PROJECTS_FILE` to a tmp path.
- Spawn the built `node packages/cli/dist/index.js` binary (or import the command functions with the env override) for the full `project add / list / switch / current / remove / doctor` lifecycle against two tmp git repos.
- Assert stdout content and JSON registry state.

Decision to make at implementation time: spawn the built binary (true E2E) vs. importing the command functions (faster, no build dependency). Recommendation: import the functions and intercept stdout — keeps the test in vitest, no build artifact dependency, still hits the same code paths.

### Session observability

`SessionMeta` additions (in `packages/shared/src/types.ts`):

```ts
interface SessionMeta {
  // existing fields...
  startedAt?: string;       // when run/handoff command kicked off
  endedAt?: string;         // when status moved to completed/failed
  durationMs?: number;      // endedAt - startedAt
  handoffCount?: number;    // total handoffs generated this session
}
```

`run` and `handoff` update `startedAt` on entry, `endedAt` + `durationMs` on exit, and bump `handoffCount` after a successful handoff write.

New command:

```bash
relay-baton handoff history [--project <name-or-id>] [--path <repoPath>]
```

Behavior:

- Lists files matching `.ai-session/handoff.*.md` (the backup pattern from `SessionManager.backupHandoffIfExists`) plus the current `handoff.md`.
- Columns: timestamp, size, first non-empty content line as a label.
- No content dump — just metadata.

## Compatibility Notes

- `SessionMeta` fields are additive. Existing `.ai-session/session.json` files keep working; new fields are populated on the next `run` / `handoff`.
- `handoff history` is a new subcommand; nothing renamed.
- CI workflow does not affect runtime behavior.
- No breaking change planned. If a test reveals a bug in v0.3 quality-gate logic, a fix will land in v0.3.x rather than mutating v0.4 scope.

## Order of Work (suggested)

This is the order I'd take it in tomorrow:

1. **CI first** — `.github/workflows/ci.yml`. Even before adding tests, this enforces that whatever exists today keeps passing. ~15 min.
2. **CLI smoke test** — high-leverage, exercises the v0.2 / v0.3 project layer end-to-end. ~45 min.
3. **Quality gate tests** — `HandoffQualityGate` + `TokenDietQualityGate`. Small, pure functions, easy wins. ~45 min.
4. **HandoffGenerator + BatonWorkflow tests** — bigger, may surface real bugs. Plan ~1.5h.
5. **ClaudeCodeAdapter test** — mirror of the existing `CodexAdapter.test.ts`. ~20 min.
6. **Session observability** — types + `run` / `handoff` instrumentation + `handoff history` command + test. ~1.5h.
7. Bump versions to 0.4.0, finalize this note (drop the "Planning" header, add real Summary stats), tag.

If time runs out, item 6 is the most droppable — observability is nice-to-have, the testing items are the actual safety net.
