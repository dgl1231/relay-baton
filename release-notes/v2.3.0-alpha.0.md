# v2.3.0-alpha.0 — Multi-agent breadth

v2.3 "Multi-agent breadth" — make relay-baton agent-agnostic beyond the
Codex↔Claude pair. Both roadmap items ship in this alpha.

## Added

- **First-class multi-agent matrix.** A central agent registry
  (`packages/core/src/agents/AgentRegistry.ts`) is the single source of truth for
  every agent: support tier (`first-class` for codex/claude vs `supported`),
  install URL, login spec, default subprocess args, and agent-specific fallback
  patterns. OpenCode / Gemini / Aider are promoted from scaffolds to **supported**
  adapters, and the **Cursor CLI** (`cursor-agent`) is added behind the same
  `AgentAdapter` contract (`AgentId` gains `cursor`).
  - `relay-baton login [agent]` is now registry-driven and covers all six agents
    (subcommand logins, interactive logins, and env-key agents like Aider).
  - `relay-baton doctor` reports availability **and tier** for every agent;
    `ConfigSchema` and `diagnostics` derive their agent lists from the registry,
    so the matrix never drifts.
- **N-way & reverse relay.** `relay-baton run` is now a generalized relay loop
  over an ordered agent chain instead of a hardcoded codex→claude pair. The
  deterministic "who's next" policy: `--chain a,b,c` wins, else
  `--primary`/`--fallback`, falling back to project overrides, then config. This
  enables **reverse relay** (e.g. `--primary claude --fallback codex`) and longer
  N-way chains; each hop builds and gates a handoff and uses the active agent's
  fallback patterns. `PromptBuilder.continuation()` is now agent-agnostic.

## Hard constraints

Unchanged: local subprocess only, no direct LLM API client, no API-key
passthrough by default, no approval-bypass flags in any default args, no auto
commit/push/PR.
