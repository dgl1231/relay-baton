# relay-baton v0.6.0 릴리즈 노트

상태: **Planning** — 작업 spec. 항목 완료되면 릴리즈 노트로 전환.

목표 날짜: 2026-08

## 요약

v0.6은 v0.4/v0.5에서 미룬 surface를 마무리하고 v0.5의 두 mode를 심화한다. 신규 mode 없음. 테마: **plan-execute와 context-compression을 견고하고 보이게.**

블록은 독립적으로 선택 가능. 최소 = 블록 A.

## 블록 A — 신규 mode용 UI (v0.5 이월)

- TUI 패널: 현재 `workflowMode`, plan 상태(`planning`/`plan_ready`/`executing`), `compressing` 표시.
- TUI 키 기존(`q`/`r`/`p`/`d`/`b`/`h`)에 `e` = execute preview(agent 실행 없음 — TUI는 절대 spawn 안 함) 추가.
- `status` 명령: plan-execute 필드(planAuthor/executor/planFinalizedAt) + 마지막 압축 ratio 표시.
- 파일: `packages/tui/src/App.tsx`, `packages/cli/src/commands/status.ts`.

## 블록 B — Plan-execute 심화

- **Plan execution receipts** — executor가 `plan.md` Steps에 `[done]`/`[skipped]` 마킹. 검증 가능한 trail. Gate: marker만 append, step 텍스트 재작성 금지.
- **Plan diffing** — 재계획 시 전체 재작성 대신 이전 `plan.md` 대비 delta 표시. 이전본은 `plan.<ts>.md`로 보관(handoff backup 미러).
- **Multi-turn loop** — executor가 divergence를 `errors.md`에 기록; `plan --replan`이 errors를 입력으로 planner 재진입. budget guard: loop 상한(예: 3)으로 token 폭주 방지.
- 파일: `packages/core/src/plan/*`, `packages/cli/src/commands/{plan,execute}.ts`.

## 블록 C — Context-compression 심화

- **Adaptive per-model threshold** — active agent의 알려진 context 크기에 맞춰 threshold 조정. config: `contextCompression.perAgentThreshold`.
- **Cross-session 압축** — 완료된 과거 세션의 raw artifact를 archive 디렉터리로 통합(각 `.ai-session/`에 방치하지 않음).
- **Semantic summarization** — 비용 제한 + 결정적 fallback 설계가 나오기 전까지 **여전히 보류**. MVP 규칙(relay-baton 프로세스 내 API 호출 없음) 유지.
- 파일: `packages/core/src/token-diet/ContextCompressor.ts`.

## 블록 D — Adapter + CI matrix (v0.4/v0.5 이월)

- OpenCode / Gemini / Aider adapter scaffold — 실제 사용자가 필요로 할 때만. 각각 = `<Name>Adapter.ts` + mirror 테스트 1개 + README 행.
- Project-level fallback pattern override — `BatonProject.fallbackPatterns?`가 global 위에 덮어쓰기.
- macOS / Windows CI matrix — `.github/workflows/ci.yml`에 `matrix.os`. Windows path/EOL fix 최소 1개 예상.

## 호환성

- 전부 additive. 신규 config 키 optional. 신규 SessionMeta 필드 optional.
- `plan.<ts>.md` backup은 기존 `handoff.<ts>.md` 패턴 미러.
- breaking change 계획 없음.

## 작업 순서 (추천)

1. 블록 A (UI) — 작고 가시성 높음. ~1.5h.
2. 블록 B receipts + diffing — ~2h. multi-turn loop는 마지막(가장 위험).
3. 블록 C adaptive threshold — ~1h. cross-session — ~1.5h.
4. 블록 D는 필요 시 / CI 비용 수용 시에만.
5. 0.6.0 bump, 노트 finalize, tag.

v0.6 최소 = 블록 A. 나머지 layered.

## Out of scope

- 실시간 agent chat / DM.
- 자체 LLM API client.
- 자동 commit/push/PR.
- IDE extension, daemon, tmux manager.
