# v2.3.0-alpha.0 — Multi-agent breadth (멀티 에이전트 확장)

v2.3 "Multi-agent breadth" — relay-baton을 Codex↔Claude 쌍을 넘어 에이전트
불특정으로 만든다. 두 로드맵 항목을 이 alpha에서 모두 출하한다.

## 추가

- **First-class 멀티 에이전트 매트릭스.** 중앙 에이전트 레지스트리
  (`packages/core/src/agents/AgentRegistry.ts`)가 모든 에이전트의 단일 진실
  공급원: 지원 tier(codex/claude는 `first-class`, 나머지는 `supported`), install
  URL, login spec, 기본 subprocess args, 에이전트별 fallback 패턴. OpenCode /
  Gemini / Aider를 scaffold에서 **supported** 어댑터로 승격하고, **Cursor CLI**
  (`cursor-agent`)를 동일한 `AgentAdapter` 계약으로 추가했다(`AgentId`에 `cursor`).
  - `relay-baton login [agent]`가 레지스트리 기반이 되어 6개 에이전트를 모두
    지원한다(subcommand 로그인, 대화형 로그인, Aider 같은 env-key 에이전트).
  - `relay-baton doctor`가 모든 에이전트의 가용성과 **tier**를 함께 보고하고,
    `ConfigSchema`/`diagnostics`가 레지스트리에서 목록을 도출해 매트릭스가
    어긋나지 않는다.
- **N-way & reverse relay.** `relay-baton run`이 하드코딩된 codex→claude 쌍 대신
  순서가 있는 에이전트 체인을 도는 일반화된 릴레이 루프가 되었다. 결정적
  "who's next" 정책: `--chain a,b,c`가 우선, 없으면 `--primary`/`--fallback`,
  이어서 프로젝트 오버라이드, 그다음 config. 이로써 **역방향 릴레이**
  (예: `--primary claude --fallback codex`)와 더 긴 N-way 체인이 가능하다. 각
  hop마다 handoff를 빌드·게이트하고 활성 에이전트의 fallback 패턴을 쓴다.
  `PromptBuilder.continuation()`은 이제 에이전트 불특정이다.

## 하드 제약

변동 없음: local subprocess 전용, 직접 LLM API client 없음, 기본적으로 API key
env 미전달, 기본 args에 approval-bypass 플래그 없음, 자동 commit/push/PR 없음.
