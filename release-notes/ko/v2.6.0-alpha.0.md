# v2.6.0-alpha.0 — Multi-session workspace (멀티 세션 워크스페이스)

v2.6 "Multi-session workspace" — 한 repo에서 여러 AI 작업(work item)을 추적하고,
각각을 에이전트에 지정하며, git 충돌 없이 병렬로 돌린다. "AI별 세션 지정"과
"다중작업"을 하나의 개념 — *named work item* — 으로 통합한다. 세 로드맵 항목을 이
alpha에서 모두 출하한다. (하드 제약 유지: local-first, deterministic, no daemon,
no real-time chat.)

## 추가

- **Named sessions (work-item 레지스트리).** `WorkspaceManager`가
  `.ai-session/workspace.json`(active 포인터 + work-item 목록)을 소유한다. named
  항목은 `.ai-session/sessions/<name>/` 아래에 있고, 레거시 flat `.ai-session/`이
  곧 `default` 항목이라 기존 repo는 **마이그레이션이 필요 없다**. `SessionFiles`가
  active 항목을 해석하므로 모든 명령(`run`/`handoff`/`status`/`usage`/…)이 투명하게
  그 위에서 동작한다. 신규 CLI: `session new | switch | use | items | assign |
  remove`.
- **Per-agent session assignment.** 각 work item은 `assignedAgent`를 가질 수 있다
  (`session new --agent <id>` / `session assign <name> <agent>`). `run`이 이를
  relay chain의 기본 primary로 쓴다 — project/config 기본값을 이기고, 명시적
  `--primary`/`--chain`에는 진다.
- **git worktree로 안전한 병렬.** `session worktree add <name>`이 work item을 자체
  git worktree로 받친다(기본 `<parent>/<repo>.worktrees/<name>`, 브랜치
  `relay/<name>`). active 항목에 worktree가 있으면 `run`이 그 격리된 checkout
  (자체 working tree + 자체 `.ai-session`)에서 실행되어, 병렬 work item들이 서로의
  git 상태를 덮어쓰지 않는다. 레지스트리는 메인 repo에 남는다. 여전히
  confirmation-first, daemon 없음. `session worktree remove <name>`로 분리한다.

## 하드 제약

변동 없음: local subprocess 전용, deterministic, daemon 없음, 실시간 chat
플랫폼 없음, 직접 LLM API client 없음, 기본 API key 미전달, 자동 commit/push/PR
없음.
