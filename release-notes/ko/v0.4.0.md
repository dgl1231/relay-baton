# relay-baton v0.4.0 릴리즈 노트

상태: **Planning / 진행 중** — 이 문서는 v0.4의 작업 spec이다. 항목이 완료되면 최종 릴리즈 노트로 바뀐다.

목표 날짜: 2026-06

## 요약

v0.4.0은 "harness를 믿을 수 있게" 만드는 버전이다. v0.2는 multi-project layer를 추가했고 v0.3은 안전하게 만들었다. v0.4는 *fallback path 자체*를 관측 가능하고 검증 가능하게 만든다.

문제: harness가 Codex → Claude handoff 과정에서 조용히 잘못된 동작을 하면 지금은 알 방법이 없다. 핵심 orchestration 코드에 테스트가 없고, harness가 duration / history signal을 안 남기기 때문이다.

범위는 일부러 좁힘:

- workflow / handoff / quality-gate 경로의 테스트 커버리지.
- push / PR에 대한 CI.
- project 명령어의 end-to-end CLI smoke test.
- `session.json`에 session duration 추가, `handoff history` 명령어 추가.

명시적 out-of-scope (v0.4를 작게 유지하기 위해):

- OpenCode / Gemini / Aider adapter — v0.5로 미룸.
- TUI fuzzy switcher / command palette.
- Per-model tokenizer, semantic diff, autopilot. `CLAUDE.md`의 MVP 정책 위반.

## 계획된 변경

### Critical path 테스트 커버리지

매 fallback launch에 참여하는데 테스트가 없는 모듈:

- `packages/core/src/workflow/BatonWorkflow.ts` (124 LoC, 0 tests) — handoff payload 조립.
- `packages/core/src/handoff/HandoffGenerator.ts` — `handoff.md` 작성.
- `packages/core/src/handoff/HandoffQualityGate.ts` — handoff가 불완전하면 fallback 차단.
- `packages/core/src/handoff/TokenDietQualityGate.ts` — budget 초과 시 fallback 차단.
- `packages/core/src/agents/ClaudeCodeAdapter.ts` — Codex adapter는 테스트 있는데 Claude쪽은 없음.

타깃:

- BatonWorkflow: fixture `.ai-session/` 디렉토리 기반 end-to-end handoff build. 결과 `handoff.md`에 task, repo map 참조, fallback reason이 들어가고 profile budget 안에 들어오는지 검증.
- HandoffGenerator: section 순서, reference-only 출력 (full diff inline 금지), 덮어쓰기 시 backup 동작.
- HandoffQualityGate: gate 실패 사유별 pass / fail.
- TokenDietQualityGate: profile별 pass / warn / fail.
- ClaudeCodeAdapter: 기본 args (`--permission-mode acceptEdits -p "<prompt>"`), `--allow-api-key-env` 없을 때 env filtering.

### CI 워크플로우

`.github/workflows/ci.yml` 추가:

- Trigger: `main` push, pull_request.
- Steps: checkout, Node 20 + corepack 설정, `pnpm install --frozen-lockfile`, `pnpm build`, `pnpm test`.
- Matrix: `ubuntu-latest` 하나만. macOS / Windows는 비용이 싸지 않으면 v0.5로 미룸.

이전 릴리즈 노트에서 제거한 수동 "Validation" 섹션을 CI가 대체한다.

### CLI smoke test

`packages/cli/src/__tests__/project.smoke.test.ts`:

- `RELAY_BATON_PROJECTS_FILE`을 tmp 경로로 설정.
- 두 개의 tmp git repo를 대상으로 `project add / list / switch / current / remove / doctor` 전체 lifecycle 실행.
- stdout 내용과 JSON registry 상태 검증.

구현 시 결정할 것: 빌드된 binary spawn (진짜 E2E) vs. command function import (빠름, build 의존성 없음). 추천: function을 import하고 stdout intercept — vitest 안에 머무르고, build artifact 의존 없고, 같은 코드 경로를 거침.

### Session 관측성

`packages/shared/src/types.ts`의 `SessionMeta`에 추가:

```ts
interface SessionMeta {
  // 기존 필드들...
  startedAt?: string;       // run/handoff 명령 시작 시점
  endedAt?: string;         // status가 completed/failed로 바뀐 시점
  durationMs?: number;      // endedAt - startedAt
  handoffCount?: number;    // 이 session에서 생성된 총 handoff 수
}
```

`run` / `handoff`가 진입 시 `startedAt`, 종료 시 `endedAt` + `durationMs` 갱신. handoff write 성공 후 `handoffCount` 증가.

신규 명령어:

```bash
relay-baton handoff history [--project <name-or-id>] [--path <repoPath>]
```

동작:

- `.ai-session/handoff.*.md` (SessionManager의 backup 패턴) 와 현재 `handoff.md`를 나열.
- 컬럼: 타임스탬프, 크기, 비어있지 않은 첫 줄을 label로.
- 본문 dump 없음 — metadata만.

## 호환성

- `SessionMeta` 필드는 추가형. 기존 `.ai-session/session.json`은 그대로 동작하고, 다음 `run` / `handoff`에서 새 필드가 채워진다.
- `handoff history`는 신규 subcommand. 이름 변경 없음.
- CI 워크플로우는 런타임 동작에 영향 없음.
- breaking change 계획 없음. 테스트로 v0.3 quality-gate 로직 버그가 발견되면 v0.3.x로 fix하고 v0.4 범위는 안 흔든다.

## 작업 순서 (추천)

내일 회사에서 이 순서로 진행 추천:

1. **CI 먼저** — `.github/workflows/ci.yml`. 테스트 추가 전이라도 "지금 통과하는 게 계속 통과"가 강제됨. ~15분.
2. **CLI smoke test** — leverage 높음. v0.2 / v0.3 project layer end-to-end. ~45분.
3. **Quality gate 테스트** — `HandoffQualityGate` + `TokenDietQualityGate`. 순수 함수, 작은 작업. ~45분.
4. **HandoffGenerator + BatonWorkflow 테스트** — 큰 작업. 실제 버그 나올 수 있음. ~1.5시간.
5. **ClaudeCodeAdapter 테스트** — 기존 `CodexAdapter.test.ts` mirror. ~20분.
6. **Session 관측성** — types + `run` / `handoff` 계측 + `handoff history` 명령어 + 테스트. ~1.5시간.
7. version 0.4.0 bump, 이 노트 마무리 ("Planning" 헤더 제거, 실제 Summary 통계 추가), tag.

시간 부족하면 6번이 가장 드랍하기 쉬움. observability는 nice-to-have, 테스트가 실제 safety net.
