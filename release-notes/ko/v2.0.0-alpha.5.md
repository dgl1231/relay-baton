# v2.0.0-alpha.5 — 세션 prune 정책

마지막 남은 v1.6 기능과 CI 신뢰성 수정, 그리고 로드맵 마커 정리를 마무리합니다.
결정적·안전 우선.

## 추가

- **세션 아카이브 prune 정책** — `relay-baton session prune [--max-age-days <n>]
  [--max-count <n>] [--apply] [--json]`. 기본 비활성(정책 없으면 아무것도 prune
  안 함)이고 **기본 dry-run** — 후보만 미리보고 `--apply`일 때만 삭제한다. 주어진
  제약을 하나라도 위반하면 prune(N일보다 오래됨, 또는 최신 N개 밖). `createdAt`을
  알 수 없는 아카이브는 나이 기준으로 절대 prune하지 않는다.

## 수정 (CI, alpha.4 이후 `main`)

- 릴리즈 워크플로의 병렬 빌드 매트릭스가 GitHub Release 생성을 두고 경쟁해 한 잡이
  "tag_name already_exists"로 실패했다. 이제 전용 `create-release` 잡이 매트릭스가
  에셋을 올리기 전에 릴리즈를 한 번만 생성한다. `RELEASE.md`에 문서화. (이번
  릴리즈부터 적용.)
