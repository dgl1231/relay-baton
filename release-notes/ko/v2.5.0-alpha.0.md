# v2.5.0-alpha.0 — Guarded automation & extensibility (가드된 자동화 · 확장성)

v2.5 "Guarded automation & extensibility" — 더 길지만 제한된(bounded) 실행과
프로젝트별 커스터마이즈. 무인 데몬은 절대 아니다. 두 로드맵 항목을 이 alpha에서
모두 출하한다.

## 추가

- **Bounded auto-orchestration (`run --until <n>`).** 새 core
  `BoundedOrchestrator`가 `LoopController`(스텝/예산/divergence 캡)와 결정적
  `GuardrailPolicy`(변경 파일/스텝/예산 캡)를 하나의 "한 스텝 더 가도 되나?"
  결정으로 결합한다. `run --until N`은 방금 끝낸 에이전트에서 **최대 N개의 추가
  continue 스텝**을 실행하되 **confirmation-first**(각 스텝은 `--yes`가 없으면
  확인 요청)이며, 스텝마다 실행 checkpoint와 usage 이벤트를 기록한다. 엄격히
  bounded: 스텝 캡, 예산 상한, divergence, guardrail 위반, 확인 거부 중 하나라도
  걸리면 멈춘다. **무인 데몬이 아니다** — 캡이나 확인 게이트를 제거하는 것은
  설계상 범위 밖이다.
- **Project recipes / hooks.** config의 선택적 `hooks.preHandoff` /
  `hooks.postExecute` 셸 명령 배열을 새 core `HookRunner`가 라이프사이클
  지점에서 실행한다. **로컬 전용:** child env는 에이전트와 동일하게 정화되고
  (provider API key 기본 제거), 데몬 없음, 네트워크 없음. config가 없으면 아무것도
  실행되지 않고, 첫 실패 명령에서 체인이 멈추며, 모든 출력은 `commands.log`로
  미러링된다. `run`과 `handoff`에 연결됨.

## 하드 제약

변동 없음: local subprocess 전용, 결정적, 변경 루프는 confirmation-first, 무인
autopilot 없음, 직접 LLM API client 없음, 기본 API key 미전달, 네트워크 없음,
자동 commit/push/PR 없음.
