# v1.4.0 — 友善的 agent 輸出串流 & 桌面端結果卡片

agent 輸出終於讀起來像對話，而不是日誌傾印 — CLI 和桌面應用皆然。

## `--pretty`：友善的 agent 輸出串流（CLI）

`run`、`plan`、`execute`、`handoff` 新增可選的 `--pretty` 旗標。它向 agent
CLI 要求機器可讀的事件串流（`claude -p --output-format stream-json
--verbose`、`codex exec --json`），並渲染為易讀的行：

```
● model claude-sonnet-5 · session abc123
  · thinking: need to look at the failing test first
→ Bash: pnpm test --filter core
Fixed the flaky test — two files changed.
✓ agent turn done — in 10,231 tok · out 1,892 tok · $0.0231 · 48.2s
```

- 僅使用確定性的逐行 JSONL 解析 — 不呼叫模型、不做摘要（Codex/Claude
  adapter 的 `parseEvent`）。
- 無法解析的行，以及沒有結構化模式的 agent，回退為原樣透傳；完整原始串流仍
  寫入 `.ai-session/commands.log`。
- fallback 偵測不變：模式繼續在原始行上比對，包括 JSON 事件內的錯誤文字。
- 因舊版 agent CLI 可能不支援這些旗標，故為可選。

## 桌面端：Agent Room 結構化結果卡片

斜線指令結果（`/status`、`/budget`、`/git`、`/review`、`/guard`、`/risk`、
`/checkpoints`、`/sessions`、`/resume`、`/workspace`、`/profile`、
`/inventory`、`/inspect`、`/bundle`）現在渲染為結構化卡片 — 狀態徽章、
budget 進度條、git 逐檔案行、plan 步驟清單 — 而非原始 `JSON.stringify`
傾印。每張卡片都在收合的 **raw json** 區段保留完整 payload，資訊零遺失。
全部為僅顯示的 DOM 建構器；webview 仍不包含業務邏輯。

修正：`/review` 結果在渲染後立即被時間軸重載清除的問題。

## 相容性

- `--pretty` 為可選；預設輸出不變。
- `AgentEvent` 新增事件類型（`system`、`assistant_text`、`reasoning`、
  `tool_use`、`usage`）— 僅為增量，不影響既有使用方。
- 無 config 或工作階段 schema 變更。
