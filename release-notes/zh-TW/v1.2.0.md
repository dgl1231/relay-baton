# v1.2.0 — 更聰明的接力 & 友善的 UI

> 註:v1.1.x 的標籤名已被 GA 前的「Distributable」線使用,因此 GA 後的第一個功能版本以 v1.2.0 發佈。

作為 GA 後的第一個功能版本,收錄了 v2.8「Smarter relay」以及 CLI/桌面的體驗改進。硬性限制不變:本地優先、確定性、僅 subprocess、confirmation-first、無常駐程式。

## 新增

- **擴充的接力觸發(opt-in)。** 新增可選設定 `handoffTriggers`(`budgetRatio` / `changedFiles` / `usageTokensProxy`):即使沒有出現 fallback 錯誤模式,也會 *建議* 交棒。達到門檻時 y/N 確認(或 `--yes`);未設定則維持僅依錯誤模式偵測。核心:`HandoffTriggerPolicy`。
- **手動接力觸發。** `relay-baton run --handoff-now` 不等待 fallback 訊號,在每個 hop 之後交給下一個 agent(此旗標本身即為明確同意)。
- **建議性路由提示。** 註冊表中的 agent 新增 `strengths` 關鍵字標籤;`suggestChain` 為任務提出鏈路順序建議,僅當順序不同時 `run` 才輸出一行提示。僅顯示 — 明確的 `--chain`/`--primary` 永遠優先。

## 改進

- **友善的 CLI 輸出。** 零相依的 `ui` 輔助(✓ / ✗ / ▲ / → 以及「接下來該做什麼」的提示);`run` 輸出改用 hop 標題與更清楚的 gate 失敗顯示。管線輸出或設定 `NO_COLOR` 時自動關閉顏色。
- **桌面暖色重塑。** Tauri webview 採用暖色調色盤(奶油色淺色、暖色深色、赤陶強調色)、介面使用無襯線字體、更柔和的圓角/陰影,以及訊息卡片式的對話事件。僅顯示 — webview 仍然只呼叫 CLI sidecar。

## 修正

- 當 stdin 不是 TTY(CI/管線)時,`run` 的確認提示不再永久卡住 —— 會自動拒絕並提示傳入 `--yes`。
- Windows CI:worktree 測試的路徑比較現在會展開 8.3 短路徑。

## 相容性

- 無破壞性變更。新設定鍵 `handoffTriggers` 為可選並會被驗證;工件 schema 未變。
