# v1.4.0 — 友好的 agent 输出流 & 桌面端结果卡片

agent 输出终于读起来像对话，而不是日志转储 — CLI 和桌面应用都是如此。

## `--pretty`：友好的 agent 输出流（CLI）

`run`、`plan`、`execute`、`handoff` 新增可选的 `--pretty` 标志。它请求
agent CLI 的机器可读事件流（`claude -p --output-format stream-json
--verbose`、`codex exec --json`），并渲染为易读的行：

```
● model claude-sonnet-5 · session abc123
  · thinking: need to look at the failing test first
→ Bash: pnpm test --filter core
Fixed the flaky test — two files changed.
✓ agent turn done — in 10,231 tok · out 1,892 tok · $0.0231 · 48.2s
```

- 仅使用确定性的逐行 JSONL 解析 — 不调用模型、不做摘要（Codex/Claude
  adapter 的 `parseEvent`）。
- 无法解析的行，以及没有结构化模式的 agent，回退为原样透传；完整原始流仍
  写入 `.ai-session/commands.log`。
- fallback 检测不变：模式继续在原始行上匹配，包括 JSON 事件内的错误文本。
- 由于旧版 agent CLI 可能不支持这些标志，因此为可选。

## 桌面端：Agent Room 结构化结果卡片

斜杠命令结果（`/status`、`/budget`、`/git`、`/review`、`/guard`、`/risk`、
`/checkpoints`、`/sessions`、`/resume`、`/workspace`、`/profile`、
`/inventory`、`/inspect`、`/bundle`）现在渲染为结构化卡片 — 状态徽章、
budget 进度条、git 逐文件行、plan 步骤清单 — 而非原始 `JSON.stringify`
转储。每张卡片都在折叠的 **raw json** 区域保留完整 payload，信息零丢失。
全部为仅显示的 DOM 构建器；webview 仍不包含业务逻辑。

修复：`/review` 结果在渲染后立即被时间线重载清掉的问题。

## 兼容性

- `--pretty` 为可选；默认输出不变。
- `AgentEvent` 新增事件类型（`system`、`assistant_text`、`reasoning`、
  `tool_use`、`usage`）— 仅为增量，不影响现有使用方。
- 无 config 或会话 schema 变更。
