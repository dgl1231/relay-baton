# v1.5.0 — 在桌面应用中运行 agent

Agent Room 不再只是查看器：现在它可以真正启动 agent — **确认后执行
（confirmation-first）**，正如 AGENT_ROOM 设计文档从一开始就规定的那样
（preview → confirm → run）。未经点击，任何东西都不会运行。

## `/run <task>` 与"在此运行"

- 新的 **`/run <task>`** composer 命令：构建
  `relay-baton run "<task>" --primary <所选 agent> --pretty` — 顶部的
  Codex/Claude 切换现在真正决定谁先上场。
- **`/plan`、`/execute`、`/handoff`** 也会构建真实的启动命令
  （handoff 移除了 `--no-run`）。
- 以上命令都会在现有确认弹窗中显示**精确命令**；新的**"在此运行"**按钮
  通过打包的 sidecar CLI 执行（使用你本地的 agent 登录/配额 —
  relay-baton 仍然从不直接调用 provider API）。复制到终端的选项保留。

## 实时运行卡片

agent 输出以实时卡片形式流入时间线（`--pretty` 格式）：工具调用、
assistant 文本、结尾的 token/费用回执实时出现。**取消**按钮可终止进程；
结束时卡片会带上绿色 `完成` 或红色 `exit N` 徽章，并刷新仪表盘面板。
同时只允许一个运行；输出保留最近 400 行；卡片像 v1.4.1 的结果卡片一样
在时间线重载后保留。

## 底层 / 兼容性

- Tauri capability 新增：sidecar 范围的 `shell:allow-spawn` 与用于取消的
  `shell:allow-kill`（仅有 execute 会拒绝流式运行）。
- GUI 仍然不含业务逻辑：只是 spawn CLI 并显示行。所有关卡（handoff 质量、
  token diet、redaction、guardrail）都和终端里一样在 CLI 内运行。
- 指南/提示文案在 GUI 全部 4 种语言中更新 — 应用现在是"确认后执行
  仪表盘"，而非只读。
- CLI 行为不变；版本同步递增。
